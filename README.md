# 0.5.6 发送者分路试验版

新增按发消息的小号 QQ 路由到独立 Tunnel，共用全局运行密钥。空路由列表保持旧单路行为。每路独立消息、附件、回调状态；接收权限与管理员权限不扩大。配置、限制与回退见 [UPDATE_0_5_6.md](UPDATE_0_5_6.md)。

# ChatGPT Dot MCP助手

让 ChatGPT Dot 接收并回复获准的 QQ 私聊与群消息，支持图片、文件和本地消息记录。AstrBot 原生插件，目标版本 **AstrBot 4.28.2**，使用已有的 `aiocqhttp` 适配器。

当前版本 **v0.5.6 发送者分路试验版**：[配置、隔离边界与回退](UPDATE_0_5_6.md)。此前更新：[原文件事件服务提示及兼容风险](UPDATE_0_5_5.md)；[处理观测与有限提醒](UPDATE_0_5_4.md)；[群文件使用说明](UPDATE_0_5_2.md)。旧固定对话可用已有 qq_reply 显式回传附件；无需靠重开对话取得新工具。

## 开始使用

1. 备份插件配置和数据，再从 AstrBot 插件管理通过 [公开仓库](https://github.com/ColoNoko/astrbot-dot-mcp) 原位安装或更新。插件默认关闭；`dist` 内 v0.3.2 ZIP 仅为历史存档，不是当前安装包。完整步骤见 [安装教程](INSTALL.md)。
2. 在常规配置填写「管理者 QQ」和「私聊 QQ」，通过「群规则 → 添加条目 → 群规则」逐群设置接收条件。
3. 打开插件「连接设置」，选择 QQ 实例、填写机器人 QQ、回调域名及已有 Tunnel 信息。
4. 保存设置，确认接收范围后在常规配置开启插件，再点击「应用并重启」。不要同时编辑两处配置。
5. 将 MCP 连接到 ChatGPT Dot。需要核对工具时，点击「查询服务端工具」；客户端仍使用旧工具时按 [OpenAI 官方步骤刷新元数据](https://developers.openai.com/plugins/deploy/connect-chatgpt#refresh-metadata)。

## 可选：按发送者分路

在原生配置的「分号路由」中填写发送者 QQ、各自独立的 Tunnel ID 和本地端口，最多 16 路；三项均不得重复。全局运行密钥必须已有使用全部 Tunnel 的权限。路由映射不会授予聊天权限，仍须配置私聊名单或群规则；多路时未映射发送者不会进入 dot。留空恢复旧单路配置，修改后需重新应用。

每路独立保存消息、附件及订阅，但共用本地 MCP Bearer，适用于同一受信任管理者的小号，不能当作互不信任客户端的强多租户鉴权隔离。多路暂不支持 Dashboard 历史页或仅重连单条 Tunnel。分路不会创建独立 dot 会话、账号或模型记忆，也与小号登录的电脑无关。详见 [v0.5.6 说明](UPDATE_0_5_6.md)。

## 每个群单独设置

- **@ 时接收**：必须真实 @ 机器人，可选择所有成员或指定 QQ。
- **指定成员**：只接收名单中 QQ 的支持消息，无需 @。
- **所有成员**：接收该群所有非机器人成员的支持消息，无需 @。

每个群号只添加一次。名单中的私聊用户不会获得管理权限。新规则格式下，私聊名单或群规则为空即关闭对应范围；本次旧群升级按原成员范围收紧为仅 @ 触发，之后可逐群调整。未 @ 的消息不会被本插件拦截或入队；开启群文件缓存时，允许成员的未 @ 文件可先在 NAS 缓存，随后同群同发送者的明确文件请求才关联并唤醒。

## v0.5 要点

- 原生可重复群规则、多私聊 QQ，配置说明集中到帮助页
- 「查询服务端工具」展示当前工具及参数，只读查询不刷新 ChatGPT 客户端缓存
- ZIP 默认返回目录与原包；显式 `include_raw=false` 只查看目录
- 保留 20 MB 附件上限与 20 秒无正文进展超时；持续有进展可超过 60 秒
- QQ 消息读取仍只返回当前消息，不自动附带历史
